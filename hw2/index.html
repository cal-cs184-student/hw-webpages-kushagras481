Overview

In this assignment I built out two main things: smooth curve and surface evaluation using Bezier methods, and a set of mesh editing operations built on top of the half-edge data structure. On paper the two halves feel pretty different, but they both ended up teaching the same lesson–that geometric operations which look simple visually involve a lot of careful, tedious work under the hood.

Once I got into the habit of drawing out every half-edge before touching the code, things went much more smoothly. Loop subdivision was the most satisfying part. Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm finds a point on a Bezier curve by doing repeated linear interpolation over the control points. You pick a parameter t in [0, 1], then blend each adjacent pair of control points as \( (1-t) \cdot p_i + t \cdot p_{i+1} \) to get a new, smaller set of points. Keep doing that until you're down to one point.

What I like about this approach is that it never requires you to actually write out the full Bernstein polynomial. Each step is just a lerp, so it's easy to implement and numerically stable. Part 2: Bezier surfaces with separable 1D de Casteljau

Surfaces work by running de Casteljau twice: once in each direction. Given a grid of control points and two parameters u and v, I ran the 1D algorithm across each row at parameter u, which gives one intermediate point per row. Those points then act as control points for a new curve, which I evaluated at parameter v to get the final surface point. It's the same algorithm you already know, just applied twice in sequence. The teapot below was rendered using this method.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To get smooth shading, each vertex needs a normal that accounts for all the faces around it. I walked the incident faces using the half-edge structure, computed each face's normal via the cross product of two edge vectors, and then scaled it by the triangle's area (which is just half the cross product's magnitude) before accumulating. Once I'd summed all those weighted normals, I normalized the result.

The reason to weight by area is pretty intuitive: a big triangle touching a vertex should have more say in what direction "up" is than a tiny sliver. Without this, you'd get weird shading artifacts around irregularly tessellated regions. The difference between flat and smooth shading is pretty visible on curved surfaces like the teapot.

Part 4: Edge flip

An edge flip takes the shared edge between two triangles and rotates it so it connects the other pair of vertices instead. No new geometry is created–same number of vertices, edges, and faces–but the connectivity changes. To implement it, I listed out every half-edge in the two triangles and reassigned all their next, twin, vertex, edge, and face pointers explicitly.

My approach was to just set every pointer, even the ones that technically don't change. It takes a bit longer to write, but it saved me from a bunch of hard-to-find bugs where I assumed something "stayed the same" and it didn't. Drawing the before and after state on paper first was really helpful here.

Part 5: Edge split

Edge split places a new vertex at the midpoint of an edge, then connects it to the opposite corners of the two neighboring triangles. Two triangles become four. Unlike an edge flip, this one actually adds geometry: one new vertex, two new edges, two new faces, and three new half-edges. Then all the existing pointers in the affected region need to be updated too.

This was the most tedious of the three operations just because of how many new elements need to be wired up. Naming everything in my diagram before writing a single line of code kept me from losing track of which half-edge was which. I also had to be careful about the order I wrote the assignments in. If you read a pointer after already overwriting it, you silently get the wrong value.

Part 6: Loop subdivision for mesh upsampling

Loop subdivision both increases the resolution of a mesh and smooths it out. The tricky part is that you have to be careful about the order you do things. If you start moving vertices around before you've computed all the target positions, you'll corrupt the results for whatever you compute next. My implementation runs in this order:

  1. Compute new positions for all existing vertices ahead of time, using \( (1 - n \cdot u) \cdot \text{original\_position} + u \cdot \text{neighbor\_sum} \), where n is the vertex degree and u is a weight that varies with n. Store them without applying yet.
  2. For each edge, compute where the new midpoint vertex will go: \( \frac{3}{8}(A + B) + \frac{1}{8}(C + D) \), where A and B are the edge's endpoints and C, D are the opposite vertices in the two adjacent triangles. Again, just store this for now.
  3. Split every original edge, marking new edges and new vertices with a flag so they can be told apart from old ones later.
  4. Flip any new edge that connects an old vertex to a new vertex. This keeps the triangle layout regular.
  5. Finally, copy all the pre-computed positions into the actual vertex positions.

After each round of subdivision, sharp corners and creases soften because every vertex gets pulled toward its neighbors. If you want to preserve a sharp edge, you can pre-split along it to pin those vertices in place.
